## 5. 复现命令（评委/自查）

```powershell
# 1. 环境（Windows 11 + Python 3.13 + Node 24 + WSL2；首次需 scripts/setup-wsl-sandbox.ps1）
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\start-sandbox.ps1
.\.venv\Scripts\python.exe scripts\preflight.py        # 退出码 0 表示配置与隔离环境就绪

# 2. 启动工作台（单端口，默认 8000；本机演示用 8005）
powershell -ExecutionPolicy Bypass -File .\scripts\workbench.ps1 -Port 8005
# 打开 http://127.0.0.1:8005

# 3. 测试（不调用模型、不执行候选）
.\.venv\Scripts\python.exe -m pytest -q                 # 872 passed + 278 subtests
cd frontend; npm test; npm run build; cd ..
```

> 评委没有模型 API Key 时：工作台可浏览已有历史运行、协作图回放、项目版本与预览；新的真实模型任务需要本地 `.env` 配置 `AGENTFORGE_LLM_API_KEY`。旧工作台的"模拟演示"模式仅用于旧记录，两种模式在界面与文档中分别标识。

## 7. 官方原文要点摘录（赛题一）

- **赛题目标**：设计并实现面向多智能体协作的**编排、调度、执行与验证平台**；重点考察知识库定义与集成、Agent 团队定义、工作流编排、动态调度、自我循环（Self-Loop）、结果验证与反馈优化等全链路工程化能力。
- **必须覆盖五个核心模块**：Agent 定义与配置、工作流编排、任务调度与执行、结果验证与监控、反馈循环与优化。
- **必须有可运行原型**，不接受纯概念设计、纯 PPT 方案或无代码实现的论文综述；必须多 Agent 协作；必须包含至少一个自我循环或迭代优化机制。
- **AI/工具链**：LLM 作为推理核心；编排调度须智能化而非硬编码；鼓励 MCP、A2A、Function Calling、RAG、向量数据库、记忆管理；使用开源框架须在调度策略、验证机制或自我循环方面有明显自定义改进。
- **方案书必须包含**：选题背景与场景需求分析；平台总体架构设计与技术选型说明；Agent 角色定义、工作流设计与编排逻辑详解；调度算法与自我循环机制说明；结果验证策略与反馈优化逻辑；核心代码模块说明与系统截图；测试用例、运行效果与性能评估；人工智能使用说明（各环节 LLM/RAG/MCP 的实际作用、贡献与局限）。
- **决赛补充**：研究价值；调度与验证算法（负载均衡、DAG 动态优先级、交叉验证、基准比对）；自我循环与 Prompt 自适应；性能与压力测试（并发、延迟、成功率，与单 Agent/串行基线对比）；落地应用。
