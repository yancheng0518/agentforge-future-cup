# 对话式工作台：使用与验证记录

日期：2026-11-08。此次修改针对“用户不知道从哪里开始”的操作问题；后端模型适配、工作流、隔离与独立验收实现未改变。

## 使用路径

1. 按 README 启动 Docker、后端和前端，打开 `http://127.0.0.1:5173/`。
2. 在首页输入一句需求，或点四个示例之一。输入框下面显示识别到的任务和处理方式；固定验收契约按需展开，不填满输入框。
3. 默认使用真实模型。点“真实模型”可调整执行方式、任务范围或改成仅审查；真实调用消耗平台额度。只看演示时，主动改成“模拟演示”。
4. 点“开始任务”或按 Ctrl/Cmd+Enter，Enter 换行。运行页展示实际步骤与结果，修改、验证、过程、项目代码通过详情面板查看。
5. 修改先留在副本。可以导出代码；完成状态任务通过后可打开应用确认对话框。其他三类任务只导出，保留固定基线。
6. 左侧新建、搜索及返回历史任务。Ctrl/Cmd+K 搜索；手机通过左上导航进入。切换历史保留未提交草稿，刷新网页不保留草稿。

“新任务”从所选任务对应的示例基线开始，不继承上一份候选；完成状态任务被明确应用后，其示例基线会改变。“恢复原任务”只恢复相同需求的未完成步骤，可能继续产生模型调用。

## 实现边界

- 自然语言入口由本地规则匹配四类 Todo 任务，不是通用项目接入或模型自动理解任意需求。未知或同时涉及多类时不允许直接发送，须明确任务范围。
- 明确“只审查／不要修改”的输入保留只读意图；选择示例后改写输入会重新判断。
- 默认真实模式不会因为配置不可用而自动变成模拟。服务配置存在不等于本次模型调用成功。
- 进度来自实际节点，不显示虚构百分比。Agent 计划与执行步骤分别展示；原始事件、审查记录及配置快照保留。
- 测试结果须来自运行器、对应当前轮次与候选、匹配冻结验收。模型自报通过、旧候选或旧轮次结果不能认证当前候选。
- 历史 `succeeded` 但当前证据失效时显示警告并禁用应用。模型协议失败和代码测试失败分开，允许显示“流程失败但此前独立测试通过”的真实组合。
- 当前功能通过只覆盖固定十项验收；额外自然语言要求仍需另行验证。
