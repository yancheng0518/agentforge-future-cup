# 动态编排对话界面验证 · 2026-11-08

本轮把 `model-directed-v1` 接入浅色工作台，新增需求统一走 `POST /api/autonomous/requests`。不再把文本匹配到四项 Todo 枚举，也不让用户选择预设角色。旧 17 项工作台记录、前期三项动态内核实验及旧对照包保留；新运行写入 `.agentforge/autonomous/`。

## 使用与复现

在项目根目录先运行 `scripts/start-sandbox.ps1`，再分别启动 `scripts/backend.ps1` 和 `scripts/frontend.ps1`，访问 <http://127.0.0.1:5173>。后端启动脚本给当前进程设置 120 秒模型请求超时，退出恢复原进程变量，不改 `.env`。可用 `-ModelTimeoutSeconds` 显式调整。原 60 秒请求超时造成的失败仍保留。

直接输入功能需求、函数输入输出及边界行为，然后发送。主 Agent 先提出可执行契约和验收，经模型审查后冻结，Docker 检查未实现脚手架确实失败，再建立任意名称的任务与子 Agent。随后由主 Agent 根据结果决定继续、追加任务、取消、验证或结束。界面展示真实任务、依赖、模型调用、测试和修正结果，不使用固定百分比。

当前执行能力限于标准库 Python 多模块、JSON 可传递的函数参数与结果。不能代表任意仓库、网页、第三方依赖和持续服务开发能力。不支持的需求会明确请求补充说明；不会静默变成模拟模式。主界面直接创建真实模型任务。历史模拟运行仍按原模式标注。

本轮界面验证的精确文本位于 `output/autonomous-chat-20261108/ui-request.txt`：CSV 支出解析、精确到分、中文分类汇总、组合报告、空行与非法行边界。所有正式尝试均由浏览器输入并点击发送，不通过 API 冒充界面提交。默认预算为 40 次请求、300,000 tokens、每次最大输出 8,192、900 秒，费用以平台实际账单为准。

## 新增可信度检查

- 验收由 AI 生成，明确显示来源；不是人工独立验收。静态校验不执行生成代码。
- 契约审查单独读取原始需求、拟定规格和测试，检查数值、排序与组合一致性；字面量 Unicode 码点由主机静态计算，避免模型猜中文排序。
- 契约不通过最多重新准备一次；方案、拒绝意见、格式重试及用量全部保留。不能悄悄修改冻结验收。
- 最后结束前按当前候选哈希再次审查代码与原始需求；审查失败反馈给主 Agent，允许新增修正任务。相同候选的失败意见不会靠反复抽样洗成通过。
- Docker 通过、语义审查通过仍不是绝对业务保证。后续发现问题会追加复核记录，保留原状态和结论，在界面标为需复核。
- 项目 ZIP 含候选与哈希清单；完整运行 JSON 含事件、任务、验证与审查。新候选只写独立工作区，不直接覆盖用户项目。

第三轮输出失败的根因是新适配器遗漏既有 Omniedu DeepSeek V4 `thinking: disabled` 参数：8192 completion tokens 被隐藏推理消耗，实际正文为空或 JSON 被截断。`autonomous-4-bounded-output` 按确认的平台域名与模型系列补回该参数，并写入请求、冻结配置；输出限制另记 `output_limit`，没有提高预算或放松 AST/schema 安全校验。第四轮据此不再发生格式失败。

第四轮之后改为 `autonomous-5-proportional-review`：修订时将完整前一版方案与意见一同交回模型，避免仅凭检查意见重新扩张需求；准备阶段采用最小一致假设、3–12 项聚焦测试。审查只将明确需求矛盾、核心行为缺失、内部冲突列为阻断，不把正确观察、可选测试建议、非 JSON 输入或未要求的策略当失败。真实排序、金额和组合冲突仍需拒绝；一次修订上限、总预算及安全门控不变。旧记录没有被静态改为通过。
