# 项目持续开发与受控运行

本阶段把现有标准库 Python 工程导入为不可变版本，在同一项目上继续输入需求。旧运行与候选目录不迁移、不重写。导入本身不执行源码，也不表示项目已经通过验证。

## 当前实现

- 浏览器选择 `.py` 文件，或通过 `POST /api/projects/import` 发送有界源码文字；服务器不接收任意主机目录或 Git 命令。
- 每次继续需求冻结项目基线、Agent 配置版本和项目资料版本；重复提交标识只返回原运行，不重复消费模型。
- 新增验收与原有回归套件分别发现，再合并执行。已有实现不替换成未实现脚手架；导入基线允许通过或失败，单独标为 `imported_baseline`。
- 主 Agent 自行拆分任务和选择自由配置的子 Agent。配置能力标签与提示词实际进入模型请求，执行文件范围仍由宿主约束；所有 Agent 当前继承比赛平台的同一模型。
- 资料只在本项目冻结的文档中检索，引用带版本、内容 hash 与节选，写入真实请求与事件。不是跨项目检索，也不是向量数据库。
- 只有当前源码 hash 对应 Docker 验收通过、需求语义审查通过，才事务性推进项目版本。失败、过期基线或哈希不匹配不会覆盖当前版本。
- 应用可选择 Python 入口与参数在 Docker 中运行。运行回执与验收测试分开；退出码 0 只说明这次应用运行成功。

## 应用数据与隔离

应用在 `/data` 工作，`AGENTFORGE_DATA_DIR=/data`。每次启动把上次成功保存的数据复制到容器 tmpfs；退出成功且导出数据有效时才提交新状态。不同项目状态隔离，同项目各版本共享应用数据；失败保留先前状态。验收容器不读取应用数据。

容器不联网、非 root、只读根目录、只读源码/运行器/输入挂载、无 capabilities，限制内存、CPU、进程数及 tmpfs。应用最多运行 15 秒，持久状态最多 32 个文件、64 KiB，拒绝链接和越界路径。所有候选 Python 均在 Docker 中运行，主机只处理文本、JSON、SQLite 与哈希。

这仍是有界 Python 工程开发环境，不提供常驻 Web 服务、数据库服务部署、第三方依赖自动安装或任意完整仓库兼容性。当前验收通过 JSON 函数接口进行；CLI、实际持久化和其他业务路径需要单独验证。

## 复现入口

运行后端与前端后，打开“项目”，导入 `examples/expense_cli/` 中两个源文件；也可通过 API 导入并提供 `benchmarks/project-workspaces/acceptance_v1.py.txt` 中的既有验收。两轮需求和项目资料位于同一 benchmark 目录。

本轮真实验证预声明位于 `output/project-workspaces-20261109/verification-declaration.json`。历史保护快照覆盖 1647 个已有文件及三套数据库，最终结果单独追加，不修改原实验。

真实同项目两轮已完成，见 [验证与全部失败记录](project-workspaces-verification.md)。主项目保存为版本 3，第二个 UI 导入检查项目仅保存未验收版本、没有调用模型。

## Codex 同类处理策略

依据 [Codex 长任务说明](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)，采用读项目、计划、编辑、执行工具、检查反馈、修正与更新记录的循环；依据[多 Agent 说明](https://developers.openai.com/api/docs/guides/agents-api/multi-agent)，独立任务可委派，短任务可由主 Agent 直接完成。

项目的持久状态、真实工具反馈、可审查版本和按需分工是本次架构方向。比赛平台模型与本地 Docker 仍负责推理和执行；这不是 Codex 内部实现或能力等同声明。

主 Agent 现可直接编辑候选、读取文件、搜索源码或调用 `run_application`，也可自行委派子 Agent。工具的 `/data` 属于本次运行专用临时状态，跨同一次运行的工具调用保留，但不会读取或更改项目真实应用数据。工具输出和修改记录进入下一轮决策与事件图；应用退出 0 不能替代冻结验收或授予完成状态。第一轮真实项目修改已观察到主 Agent 自主选择 `edit → verify → finish`，无需为了展示分工创建子 Agent。

第二轮真实观察到 `edit → tool × 5 → verify → finish`，工具执行新增、报表、删除、列表与缺失 ID 校验；负向校验的退出 1 按预期记录，未伪装成修复。读取文件支持 1-based 行范围，每次最多 400 行/16,000 字符；长单行仍可能截断，此时不能假定已完整读取。独立“新任务”保留动态派发模式，本轮直接动作仅对已导入项目开放。

最终运行器进一步区分“程序已经执行”和“状态已经保存”：并发 CAS 冲突不覆盖较新的数据，SQLite 提交状态未知或回执哈希不符时停止主 Agent，保留意图记录，避免盲目重试。该分支由故障注入平台测试验证，不算真实模型自然故障。
