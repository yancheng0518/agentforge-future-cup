## 数据与交互边界

- **入口与状态隔离：** 动态运行在未生成任务时和已有任务列表中均有“查看协作图”入口；图组件按运行 ID 重新创建会话，避免跨任务残留回放游标或选中节点。图中的历史游标按稳定事件 ID 定位，新增轮询事件不会把已停留的历史位置直接跳到末尾。
- **前缀不读取未来：** 正常回放按数值事件 ID 排序并去重；冲突或缺失关键历史时明确降级为只读最终快照。`projectFrame` 的正常路径仅归约所选事件前缀，不合并最终 `task_graph`、最终测试、最终摘要或模型用量。只有实际建任务或派发事件才能建立任务节点，主 Agent 的决定仅作为意图，拒绝决定不会伪装成执行。
- **图不是虚构聊天：** 子任务标题、指令、文件范围、依赖和 Agent ID 来自实际事件；连线表示派发、依赖、工具调用或已保存的结果反馈。位置没有承诺并发，反馈也没有被推断为自动修正成功。
- **Docker 与中断：** `verification_started` 仅显示“验收已请求 / 等待回执”，不是已执行测试。确认需最终回执同时含 `isolated=true` 与 `container_invoked=true`。实际计数读取 `test_count` 及 `attestation`。旧记录没有开始事件时不补造起点；终态仍未获完成确认的工具、任务或检查节点标记中断。
- **失败分类：** 初始脚手架/项目基线、公开预设缺陷、AI 生成验收下的候选检查、普通候选验收分别标识。AI 生成验收失败明确提示原因待核查，不把它自动解释为代码自然失败。格式错误、格式重试、模型传输失败单列，不计作代码修正。
- **事后核查：** 只有核查事件进入当前前缀后，才出现对应核查节点和否决状态；原始终态与原摘要保留。历史记录缺少逐事件来源时明确显示不能完整回放。
- **回放不会写 API：** 图组件仅依赖 React、类型与纯投影模块；播放、暂停、拖动、选节点、切换记录及回到实时均只修改前端状态，无 `fetch`、API mutation、重试、恢复或模型调用路径。App 原有任务轮询仍为读操作，并不因回放触发执行。此结论来自代码检查，浏览器网络计数由主任务另行记录。
