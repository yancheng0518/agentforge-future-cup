# 自主编排的开放任务验证包

这里的三个 JSON 文件是独立任务输入，不是引擎支持的任务枚举。引擎应接受相同结构的其他 Python 项目包，由真实主 Agent 决定拆分、依赖、子 Agent 指令以及下一步行动。旧 Todo 四类任务、旧对照实验和原始档案保持原样。

- `sales_report.json`：两个模块的 CSV 金额解析、地区汇总、端到端报告；12 个独立验收方法，含多个参数子测试。包含 CSV 引号、整型分精度、组合导入和边界阈值。起点是两个 `NotImplementedError` 脚手架，没有注入错误实现。
- `interval_library.json`：任意半开整数区间的归并、包含判断和窗口空隙；12 个独立验收方法，含多个参数子测试。一个模块，起点是未实现脚手架。模块数、函数数不强制等于子 Agent 数。
- `shipping_seeded.json`：运费规则诊断和修复；10 个独立验收方法，含多个参数子测试。源代码有明确公开的预设缺陷：不足一整公斤的附加重量被向下取整。预计原始基线有 3 个测试方法失败；实际失败数以 Docker 日志为准。需求明确要求先验证基线，再根据结果安排修复。这一用例用于验证反馈后的计划调整，不用来证明自然错误发现率。

包结构为 `requirement`、`files`、`acceptance`、`provenance`。`files` 是候选 Python 源文件字典；`acceptance` 是维护者提供、运行开始时冻结的 Python `unittest` 源码。验收父进程仅通过 `from bridge import call` 调用隔离子进程里的候选函数，不在宿主机导入候选。接口 `call(module, function, *args, **kwargs)` 只接受和返回 JSON 值，每次调用启动独立工作进程，不保留跨调用对象状态。常见 Python 内置异常由桥接器重新抛出，验收可以使用 `assertRaises(ValueError)`。

这些文件只定义任务与验收，**文件存在和语法检查不代表真实模型或 Docker 验证完成**。运行证据应另行保存在本次新建的隔离实验目录，并记录模型配置、预算、所有请求、主 Agent 决策、任务依赖、每轮候选哈希、测试输出和退出原因。

失败分类须逐项保留：

1. **未实现脚手架失败**：natural 两包在模型修改前跑测所得的 `NotImplementedError`，属于输入状态，不能计为真实模型自然代码失败。
2. **自然代码失败**：无预设缺陷干预时，真实模型产出的候选在独立 Docker 验收中失败。若没有发生，应如实记录为 0，不能为凑闭环主动改坏代码。
3. **格式重试**：模型 JSON/决策契约不合法而重发请求；独立于代码修复次数，原响应与重试仍须留存。
4. **预设缺陷失败/修复**：shipping 包的公开错误基线以及后续修复。不得混入自然代码错误统计。
5. **传输/平台/隔离失败**：HTTP、模型额度、Docker 启动、超时或观察器故障，不能计作代码功能失败。

以标准库生成并做语法检查：

```powershell
.\.venv\Scripts\python.exe .\benchmarks\autonomous\build_fixtures.py
```

该脚本只构造字符串、使用 `ast.parse` 检查语法并写出 JSON，不会执行候选实现。已有运行开始后，不应覆盖其冻结输入；重新生成源 fixture 不得改变历史运行里的快照。
